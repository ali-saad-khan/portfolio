Launchpad: Next.js SaaS Landing Page and Dashboard

A fictional SaaS for changelog hosting, built to show product-grade front end work: a marketing site with interactive pricing, and an app dashboard with a sortable table, a hand-written chart and a form with accessible validation.

The challenge

Most template-based demos hide their weaknesses behind a UI kit. I wanted to build the pieces myself, keep the logic testable, and make accessibility a feature rather than an afterthought.

There was also a practical constraint: this portfolio ships a strict Content-Security-Policy, and Next.js static export emits inline scripts that policy blocks.

How I approached it

  1. 01

    Pure logic, tested in isolation

    Pricing, filtering and sorting, KPIs, validation, chart maths and a tiny markdown renderer live in plain modules with unit tests, so the components stay thin.

  2. 02

    Interactive pricing

    A monthly or annual radio toggle and a seat calculator, with accessible radio semantics and a tested pricing module.

  3. 03

    A safe markdown preview

    The release editor previews markdown with a small custom renderer that escapes HTML first and only allows http and https links, with tests for XSS cases.

  4. 04

    Accessible forms and tables

    Custom validation uses aria-invalid and aria-describedby and moves focus to an error summary. The releases table uses aria-sort, and the delete flow is a native modal dialog.

  5. 05

    A hand-written SVG chart

    The dashboard chart is plain SVG with a data-table alternative, so there is no charting dependency.

  6. 06

    Making static export work under a strict CSP

    A documented post-build step moves Next's inline scripts into hashed files, leaving zero inline scripts, so the demo runs under script-src 'self' with no CSP exception.

Deliberate trade-offs

  • All data is mock data and the interface says so. State is stored in localStorage, and the app renders seed data first, then swaps in saved data after mount.
  • The CSP workaround post-processes Next's output and is not a supported Next feature, so it needs re-checking after upgrades. There is no Open Graph image, and I did no screen-reader testing or Lighthouse audit: accessibility was checked with component tests and manual keyboard use.

What I built

  • Designed and built the landing page: hero, features, pricing, FAQ and footer, with light, dark and system themes and no flash on load.
  • Built the dashboard: KPI cards, an SVG chart, a searchable and sortable releases table, a settings page and a release form with live preview.
  • Wrote 50 Vitest and Testing Library tests, including markdown XSS cases and the theme script.
  • Checked the demo in headless Chrome at desktop and mobile widths under the exact production CSP, and fixed a mobile overflow bug that surfaced.
  • Wrote the build step and README that explain the CSP workaround and what to re-verify after upgrading Next.
