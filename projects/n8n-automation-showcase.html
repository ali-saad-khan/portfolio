n8n Automation Showcase: Six Importable Workflows

Six n8n workflows that cover the patterns real automation work needs: API pagination, authenticated webhooks, error handling with retries, and AI classification and agents on a local model. Each one imports into n8n, and a viewer draws them from the JSON.

The challenge

Automation demos usually stop at a screenshot. I wanted workflows that anyone can import, read and check, built only from core nodes, with no credentials baked in.

They also had to show the unglamorous parts: authentication, validation, error handling and retries.

How I approached it

  1. 01

    Pagination into a CSV report

    A schedule trigger pages through an API, merges and aggregates the results, builds a CSV and uploads it with header authentication.

  2. 02

    A webhook that says no properly

    The intake webhook checks a header key, validates the payload and returns 200, 400 or 401. It then calls a sub-workflow and stores the result in an n8n Data Table.

  3. 03

    Errors that alert, and retries that back off

    A global error workflow formats and sends an alert, and a retry loop uses exponential backoff with jitter before finally stopping with an error.

  4. 04

    AI classification with structured output

    An LLM chain on a local Ollama model returns JSON for sentiment, category and urgency, with a JSON-schema output parser and an error branch.

  5. 05

    An AI agent with memory and tools

    An agent with window memory, an HTTP tool and a calculator, running against the same local model.

  6. 06

    Tooling around the workflows

    A zero-dependency validator checks structure, connections and secret-looking strings in CI, and a static SVG viewer renders each workflow from its JSON.

Deliberate trade-offs

  • The workflows import cleanly but I have not executed them end to end, so the pagination response shape and the retry loop's error handling are assumptions.
  • The $env expressions need N8N_BLOCK_ENV_ACCESS_IN_NODE=false on n8n 2.x, and a few IDs (the Ollama credential, the sub-workflow and Data Table) must be filled in after import. The README lists them.

What I built

  • Built six workflows using core nodes only, with placeholder credentials and environment-based values.
  • Imported every workflow into a real n8n 2.x container to confirm they load, and checked each node type and version against that image.
  • Wrote a validator that fails on missing connection targets, orphan nodes and literal bearer tokens, and wired it into CI.
  • Built a CSP-safe, keyboard-accessible, light and dark workflow viewer that works on static hosting.
  • Documented setup, placeholders and the patterns each workflow demonstrates.
Personal showcase project. The live page is a viewer that draws each workflow from its JSON; it does not run n8n.

What this project demonstrates

  • The core n8n skills from the Academy certificates, applied end to end
  • Authentication, validation, error handling and retries, not just happy paths
  • Local-model AI agents and structured output
  • Engineering discipline around low-code: validation, CI and docs
